# Matriz 0.1.0-rc.2 — notas da versão candidata

**Data:** 2026-11-19. **Estado:** versão candidata, **não publicada**: não tem tag nem release no GitHub. As tags `v0.1.0-rc.1` (merge do PR #29, `8824e68`) e `v0.1.0-rc.2` só são criadas depois da validação final. Não é uma release de produção.

## Porquê 0.1.0-rc.2

Segue o [Semantic Versioning 2.0.0](https://semver.org/lang/pt-BR/), com as regras das [notas da 0.1.0-rc.1](v0.1.0-rc.1.md#porquê-010-rc1):

- **0.1.0-rc.1** é o estado do merge do PR #29 (`8824e68`): é o que as notas e o CHANGELOG dessa versão descrevem, e a versão dos `package.json` passou a `0.1.0-rc.1` nesse PR.
- Depois disso entraram melhorias do frontend e o primeiro deploy online, **sem incrementos novos** e **sem mudanças no contrato da API** (`openapi.yaml` continua `0.5.0`). Uma versão menor nova (`0.2.0`) fica para quando entrar um incremento (2, 3, 7 ou 8). Continua a ser uma candidata à `0.1.0`: **rc.2**.
- Ainda não é a `0.1.0`: falta a validação final do conjunto e a aprovação. O MVP continua incompleto.

## O que não inclui (limitações conhecidas)

As da [0.1.0-rc.1](v0.1.0-rc.1.md#o-que-não-inclui-limitações-conhecidas) continuam todas, **exceto** a de "só a execução local": a aplicação está publicada online. Em resumo:

- **Incrementos por fazer:** 2 (contas, ativação e email), 7 (pedidos de responsável) e 8 (área de administração); no 3 falta a gestão da equipa. A criação de projetos só existe na API.
- **Sessão:** o token não é revogado ao sair (D06).
- **Testes E2E de browser:** um só percurso.
- **Imagem do backend:** 571 MB.

Limitações novas, do deploy no plano gratuito (D10):

- O backend para ao fim de 15 minutos sem tráfego: o primeiro pedido seguinte demora (24 s medidos a 2026-11-19; o Render indica até cerca de 1 minuto). O Neon também suspende a base de dados por inatividade.
- As migrations e o seed não correm no deploy: correm a partir de uma máquina de desenvolvimento, contra o Neon, **antes** do deploy do backend.
- O envio de email (D09) continua por decidir e por implementar.

## Como executar

Localmente, como na rc.1 ([README](../../README.md#execução-com-docker-compose)):

```bash
cp .env.example .env               # e muda os valores; JWT_SECRET: openssl rand -hex 32
docker compose up -d --build
docker compose run --rm migrate npm run db:seed   # dados de demonstração, opcional
```

Online: <https://matriz-n1k9.onrender.com> ([README, "Demo online"](../../README.md#demo-online)). A configuração do Render e do Neon está no [README, "Deploy"](../../README.md#deploy).

## Atualizar a partir da 0.1.0-rc.1

Não há migrations novas nem variáveis de ambiente novas. Basta `docker compose up -d --build` (localmente) ou o deploy automático do `main` depois de a CI passar (online).
